## Prompt

/sp.plan

Project:
Phase IV – Local Kubernetes Deployment of Cloud-Native Todo AI Chatbot

Goal:
Deploy the Phase III Todo AI Chatbot on a local Kubernetes cluster using Docker, Helm, Minikube, and AI-assisted DevOps tools, following a fully spec-driven and agentic workflow.

High-Level Strategy:
Use AI agents to generate all containerization and Kubernetes deployment artifacts. Containerize frontend and backend, package them with Helm charts, and deploy them to a local Minikube cluster. Use kubectl-ai and kagent to manage, debug, and optimize the deployment.

Deployment Plan:

Phase 1 – Environment Preparation
1. Verify Docker Desktop installation and version (4.53+ if using Docker AI Agent Gordon).
2. Enable Docker AI Agent (Gordon) in Docker Desktop (if available).
3. Install and verify Minikube.
4. Install and verify kubectl and Helm.
5. Install and verify kubectl-ai.
6. Install and verify kagent.
7. Confirm access to Phase III frontend and backend source code.

Phase 2 – AI-Assisted Containerization
1. Use Docker AI Agent (Gordon) to analyze frontend codebase.
2. Generate Dockerfile for frontend using Docker AI or Claude Code.
3. Build frontend Docker image using AI-assisted Docker commands.
4. Use Docker AI Agent (Gordon) to analyze backend + MCP server codebase.
5. Generate Dockerfile for backend using Docker AI or Claude Code.
6. Build backend Docker image using AI-assisted Docker commands.
7. Validate that both images run locally as containers.
8. Debug any container startup issues using Docker AI.

Phase 3 – Local Image Registry Strategy
1. Configure Minikube to access locally built Docker images.
2. If required, load images into Minikube or use Minikube Docker daemon.
3. Verify Kubernetes can pull and run the locally built images.

Phase 4 – Helm Chart Generation
1. Use kubectl-ai and/or Claude Code to generate Helm chart structure for frontend.
2. Define Helm templates for frontend Deployment and Service.
3. Use kubectl-ai and/or Claude Code to generate Helm chart structure for backend.
4. Define Helm templates for backend Deployment and Service.
5. Configure Helm values for:
   - Image names and tags
   - Replica counts
   - Service ports
6. Validate Helm charts using helm lint.

Phase 5 – Kubernetes Deployment via Helm
1. Start Minikube cluster.
2. Deploy frontend Helm chart to Minikube.
3. Deploy backend Helm chart to Minikube.
4. Verify Kubernetes resources using kubectl-ai:
   - Pods
   - Deployments
   - Services
5. Expose services via Minikube and validate local access.

Phase 6 – AI-Assisted Operations & Scaling
1. Use kubectl-ai to scale frontend replicas.
2. Use kubectl-ai to inspect and debug any failing pods.
3. Use kagent to analyze overall cluster health.
4. Use kagent to review and optimize resource usage if applicable.

Phase 7 – Validation & Documentation
1. Validate end-to-end application functionality.
2. Confirm frontend can communicate with backend.
3. Capture AI commands and prompts used for Docker and Kubernetes.
4. Document agentic workflow and decisions for hackathon review.
5. Confirm all requirements from Phase IV specification are met.

Risk & Fallback Plan:
1. If Docker AI Agent (Gordon) is unavailable:
   - Use standard Docker CLI commands generated by Claude Code.
2. If kubectl-ai is unavailable:
   - Use Claude Code to generate kubectl and Helm commands.
3. If kagent is unavailable:
   - Proceed with kubectl-ai for core Kubernetes operations.

Completion Criteria:
1. Both frontend and backend are running as Pods in Minikube.
2. Helm charts successfully manage deployments.
3. Services are accessible locally via Minikube.
4. AI-assisted tools are demonstrably used.
5. Deployment follows a fully spec-driven, agentic workflow.

Deliverables:
- Docker images for frontend and backend
- Helm charts for frontend and backend
- Minikube deployment running locally
- Documented AI-assisted Docker and Kubernetes operations
