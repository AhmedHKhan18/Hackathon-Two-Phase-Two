## Prompt

/sp.specify

Project Title:
Phase IV – Local Kubernetes Deployment of Cloud-Native Todo AI Chatbot

Context:
This is Phase IV of a multi-phase hackathon project. The application is a Cloud-Native Todo Chatbot developed in Phase III with basic-level functionality. The chatbot includes a frontend and backend (API + MCP server) and uses OpenAI Agents SDK for AI logic. No new application features are required in this phase.

Objective:
Deploy the existing Phase III Todo AI Chatbot on a local Kubernetes cluster using Minikube, Helm Charts, and AI-assisted DevOps tools. The deployment must follow a spec-driven, agentic development workflow with no manual coding.

Scope:
This phase focuses exclusively on infrastructure, containerization, and deployment. The goal is to containerize the application, package it using Helm, and deploy it locally on Kubernetes with AI-assisted tooling.

Functional Requirements:
1. Containerize the frontend and backend applications.
2. Use Docker Desktop for containerization.
3. Use Docker AI Agent (Gordon) for AI-assisted Docker operations such as generating Dockerfiles, building images, and debugging container issues.
4. If Docker AI (Gordon) is unavailable, fall back to standard Docker CLI commands generated by Claude Code.
5. Create Helm charts for both frontend and backend deployments.
6. Use kubectl-ai and/or kagent to generate, manage, and troubleshoot Kubernetes resources.
7. Deploy the application on a local Minikube Kubernetes cluster.
8. Ensure the frontend and backend are running as Kubernetes Deployments and exposed via Services.
9. Support basic scaling (replica count) via Helm values.

Non-Functional Requirements:
1. No manual coding of Dockerfiles, Kubernetes YAMLs, or Helm templates.
2. All infrastructure artifacts must be generated using AI agents (Claude Code, Docker AI, kubectl-ai, kagent).
3. Deployment must be reproducible using specs and generated artifacts.
4. The system must run entirely locally without any cloud services.
5. Clear separation of frontend and backend services.

AI & Agentic Dev Stack Requirements:
1. Follow the Agentic Dev Stack workflow:
   - Write specification
   - Generate deployment plan
   - Break down tasks
   - Implement via Claude Code and AI agents
2. Use Docker AI Agent (Gordon) for intelligent Docker operations.
3. Use kubectl-ai for day-one Kubernetes operations such as deployment, scaling, and debugging.
4. Use kagent for advanced Kubernetes analysis such as cluster health and resource optimization.

Technology Stack:
- Containerization: Docker, Docker Desktop
- Docker AI: Docker AI Agent (Gordon)
- Orchestration: Kubernetes (Minikube)
- Package Manager: Helm Charts
- AI DevOps Tools: kubectl-ai, kagent
- Application: Phase III Todo AI Chatbot

Deployment Targets:
- Local Kubernetes cluster using Minikube
- Frontend deployed as a Kubernetes Deployment and Service
- Backend deployed as a Kubernetes Deployment and Service

Out of Scope:
- Cloud deployment (AWS, GCP, Azure)
- CI/CD pipelines
- Monitoring and logging stacks
- New application features or business logic changes
- Manual infrastructure configuration

Assumptions:
- Phase III application source code is complete and functional.
- Docker Desktop and Minikube are available on the local system.
- kubectl, Helm, kubectl-ai, and kagent are installed or can be installed via AI-assisted instructions.

Success Criteria:
1. Frontend and backend containers build successfully.
2. Helm charts are generated and used for deployment.
3. Application deploys successfully on Minikube.
4. Pods are running and accessible locally.
5. AI tools are used and demonstrated for Docker and Kubernetes operations.
6. The entire process follows a spec-driven, agentic workflow.

Notes:
This phase emphasizes Spec-Driven Infrastructure Automation and AI-assisted DevOps. The focus is on demonstrating the use of AI agents for containerization, Kubernetes management, and deployment rather than manual infrastructure engineering.
